# Housing Registry — открытый реестр жилищного фонда России

`housing-registry` собирает публичные сведения о домах и управляющих организациях
по регионам России и предоставляет Django Admin. Требования и границы MVP-1
зафиксированы в [спецификации](docs/mvp-1-spec.md), правила работы — в [AGENTS.md](AGENTS.md).

Проект независимый и не относится к ГИС ЖКХ, Минстрою или Госуслугам.
Данные источников могут содержать ошибки и требуют проверки.

## Стек

Python 3.12+, Django 5.2, PostgreSQL, httpx, Django Admin, Docker Compose.
Локальные проверки и тесты выполняются с PostgreSQL из `.env`.

## Схема MVP-1

| Модель | Назначение |
|---|---|
| `Region` | Код, наименование, необязательный FIAS GUID и разрешение синхронизации |
| `House` | Идентификаторы, компоненты адреса, характеристики и площади |
| `Organization` | Основные реквизиты, включая ОГРН, ИНН и КПП |
| `HouseManagement` | Текущие и завершённые периоды управления, способ, основание и источник |

Один дом имеет не более одного активного периода управления. При непосредственном
управлении организация отсутствует. Окончание периода не может быть раньше начала.
Связи периодов защищены от удаления дома и организации через `PROTECT`.
ОГРН и GIS GUID организации уникальны при наличии; отсутствие ОГРН хранится как NULL.

Исходные JSON, хеши, версии домов и модель журнала импорта в MVP-1 не хранятся.

## Миграции

`0001_initial` сохранена как история исходной схемы. `0002_align_mvp1_schema`
приводит её к MVP-1 и предназначена для пустых таблиц реестра. Если в таблицах
`registry` есть данные, миграция завершится до изменений: необходим отдельный
согласованный перенос. Для новой БД применяются обе миграции последовательно.

## Локальный запуск

Сначала создайте локальный файл настроек:

```bash
cp .env.example .env
```

Перед запуском замените заглушки `DJANGO_SECRET_KEY` и `PGPASSWORD` в `.env`
на два разных случайных значения. `.env` исключён из Git; публикуйте только
`.env.example`. Django завершится с понятной ошибкой, если ключ не задан.

Django автоматически загружает `.env` из корня проекта через `python-dotenv`.
Переменные, уже заданные в окружении, имеют приоритет над значениями из файла.
Это работает для команд `manage.py`, pytest, WSGI и ASGI; вручную выполнять
`source .env` не требуется.

### Docker Compose

Compose автоматически читает `.env`. Используется встроенное описание сборки
из `docker-compose.yml`; статические файлы собираются при запуске контейнера.
Локальный `.env` в образ не копируется. Нужен Docker Compose 2.17 или новее.

```bash
docker compose up --build -d
docker compose exec web python manage.py createsuperuser
```

Админка: <http://127.0.0.1:8000/admin/>

### Python

```bash
python3.12 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python manage.py migrate
./.venv/bin/python manage.py createsuperuser
./.venv/bin/python manage.py runserver
```

## Настройка региона

Регион можно создать без FIAS GUID. Для импорта GUID должен быть заполнен,
а `sync_enabled` включён.

```bash
./.venv/bin/python manage.py configure_region \
  --code 76 --name "Ярославская область" \
  --fias-guid a84b2ef4-db03-474b-b552-6229e801ae9b
```

## Импорт

```bash
# Проверка одной страницы одного региона.
./.venv/bin/python manage.py sync_gis_houses --region-code 76 --max-pages 1 --sleep 0.25
# Полный поиск по одному региону.
./.venv/bin/python manage.py sync_gis_houses --region-code 76 --sleep 0.25
# Поиск по всем регионам с включённой синхронизацией.
./.venv/bin/python manage.py sync_gis_houses --sleep 0.25
# Повтор только отсутствующих подробных карточек.
./.venv/bin/python manage.py sync_gis_details --region-code 76 --sleep 0.25
```

Поиск выполняется страницами по 100 записей. Новые дома сохраняются по `gis_guid`;
при `detail_fetched_at=NULL` запрашивается подробная карточка. Успешные карточки
повторно автоматически не загружаются, отсутствующие в поиске дома не деактивируются.
При ошибке сохранение карточки откатывается, следующая синхронизация повторит запрос.
Статистика выводится в консоль без исходных ответов и секретов.

Используемые endpoints публичной ГИС ЖКХ:

```text
POST /homemanagement/api/rest/services/houses/public/searchByAddress
GET  /homemanagement/api/rest/services/houses/public/{typeCode}/{guid}
```

По умолчанию обрабатываются многоквартирные дома (`typeCode=1`). Для отдельного
повтора карточек другого типа используйте `sync_gis_details --type-code CODE`;
обрабатываемая выборка должна соответствовать этому типу.

Полный адрес собирается из компонентов; номер дома, корпус, литер и строение
хранятся одной строкой `building_number`. Неизвестный способ управления сохраняется
как `unknown`, основание не выводится из факта наличия лицензии.

`area_total` и `area_residential` получают отдельные показатели `totalSquare` и
`residentialSquare`. Поля площадей жилых и нежилых помещений существуют отдельно,
но автоматически не заполняются до проверки соответствующих ключей источника.
Контракт новых адресных компонентов и семантику дат необходимо проверить на
очищенных фактических ответах перед полной загрузкой региона.

Сервис `update_management` позволяет закрыть предыдущий период и создать новый.
Импортер лицензий пока не реализован: нужен отдельный подтверждённый контракт
источника. Даты выдачи лицензии нельзя подменять датами периода управления.

## PostgreSQL в Yandex Cloud

Для облачной БД укажите параметры в `.env`, настройте доступ из сети приложения
и TLS: `PGSSLMODE=verify-full`, `PGSSLROOTCERT` — путь к корневому сертификату.
Для локального PostgreSQL пример использует `PGSSLMODE=disable`.

```bash
./.venv/bin/python manage.py migrate
./.venv/bin/python manage.py createsuperuser
./.venv/bin/python manage.py collectstatic --noinput
```

Unit-файлы в `deploy/systemd/` запускают поиск по включённым регионам раз в неделю.

## Проверки

```bash
./.venv/bin/python -m pip install -r requirements-dev.txt
./.venv/bin/python manage.py check
./.venv/bin/python -m ruff check .
./.venv/bin/python -m pytest
./.venv/bin/python manage.py makemigrations --check --dry-run
```

PostgreSQL должен быть доступен. Пользователю тестовой БД необходимо право
создавать тестовую базу; pytest использует отдельную БД с префиксом `test_`.
Тесты импорта подменяют HTTP-ответы и не обращаются к ГИС ЖКХ.
